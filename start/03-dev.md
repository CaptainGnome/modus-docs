# Первый успех: consumer и `dev`

Если это первый плагин — дойдите до строки `fixture hello` в терминале. Приложение стримера не нужно. Если нужен контракт `wait` и канона — [справочник](../README.md#справочник).

Команды — из **корня** репозитория. Функция `modus` — [глава про инструменты](01-tools.md). Не делайте `cd bus`: `--manifest-path` внутри функции относительный, сломается.

## Создать каркас

```powershell
modus new consumer --id com.you.bus --dir bus
```

- `new` — записать каркас на диск, не запустить плагин.
- `consumer` — роль. Зачем она — [прошлая глава](02-roles.md).
- `--id com.you.bus` — идентификатор в манифесте. Свой второй кусок вместо `you`.
- `--dir bus` — папка каркаса относительно корня репо. Без флага папка всё равно была бы `bus` (последний кусок id); флаг делает это явным.

Вы увидите `created bus`. Внутри:

- `bus/manifest` — паспорт плагина;
- `bus/Cargo.toml` — как собирать;
- `bus/src/lib.rs` — ваш код;
- `bus/.gitignore` — не коммитить `target/`.

Папка уже есть и не пустая — отказ `bus уже существует`. Возьмите другой `--dir` (и согласуйте последний кусок `--id`, если хотите, чтобы имена совпадали).

## Запустить `dev`

```powershell
modus dev bus
```

- `dev` — собрать плагин и поднять **учебный хост в этом же процессе**. Окно Core не открывается.
- `bus` — `[PATH]`: каталог crate, не файл `.mplug` и не `src/lib.rs`.

Первый раз собирается **debug**-wasm. Это не тот модуль, что потом попадёт в `.mplug`. Может занять минуты — это сборка, не «сломался чат».

Что делает `dev`, коротко:

1. собирает wasm из `bus/`;
2. поднимает хост в CLI;
3. зовёт `init`, потом кладёт на шину два учебных события: сообщение `fixture hello` и донат;
4. крутит ваш `run`, пока вы не нажмёте Ctrl+C.

Вы увидите сначала `dev com.you.bus 0.1.0`, затем лог гостя `init`, затем строки хоста `emit … fixture hello`, затем лог плагина с тем же текстом — вроде `bus message fixture:dev … fixture hello`.

Искать нужно **вторую** фразу `fixture hello`: хост положил письмо, плагин его прочитал. Есть `emit`, нет `bus message` — не сработал `subscribe` или wasm не дошёл до `run`. Нет вообще `fixture hello` после конца сборки — не тот каталог или сборка упала (ошибка **выше** лога).

Ctrl+C — хост будит `Ready::Stop`, процесс выходит. Это штатный выход, не авария.

Остальные флаги `modus dev --help` в этой главе не нужны:

- `--inject` — свой JSON на шину, чуть ниже;
- `--token`, `--token-file`, `--account`, `--replay`, `--http-file` — коннектор, не трогайте;
- `--ui`, `--settings`, `--act` — справочник (виджет / store / act).

## Что написал `new` в `lib.rs`

Откройте `bus/src/lib.rs`. Не подставляйте чужой образец и не копируйте [`plugins/consumer`](../../plugins/consumer) — смотрите **сгенерированный** файл.

Хост зовёт три функции по очереди. В сгенерированном файле то же самое без этих комментариев — смысл такой:

```rust
// Guest — договор с хостом: должны быть init, run и shutdown.
impl Guest for Plugin {
    fn init() {
        // Короткое включение. Хост зовёт это первым, до run.
        log::log(Level::Info, "init");
        // «Кладите письма шины в мой ящик». Без subscribe цикл wait шину не увидит.
        // Подписка именно здесь: dev кладёт учебные события сразу после init.
        // Если вызвать subscribe только в run — ящик ещё закрыт, письма выкинут.
        wait::subscribe();
    }

    fn run() {
        // Единственный длинный цикл. Зовёте wait — плагин спит, хост будит.
        loop {
            match wait::wait() {
                // Штатный выход: Ctrl+C в dev, выкл в Core. Другого return из цикла нет.
                Ready::Stop => return,
                // Чужое событие с шины (фикстура, inject, коннектор). log_bus печатает текст.
                Ready::Bus(event) => log_bus(&event),
                // Пока игнорируйте: сокета, таймера и команд у consumer в dev нет.
                // Resume — только после сна Windows в Core; в dev не эмулируется.
                Ready::WsText(_)
                | Ready::WsClosed(_)
                | Ready::Timer
                | Ready::Act(_)
                | Ready::Settings
                | Ready::Resume => {}
            }
        }
    }

    // Хост зовёт после run. Сейчас пустой — так и оставьте.
    fn shutdown() {}
}

// Регистрация Plugin как гостя. Не удаляйте. Имя в скобках = struct Plugin.
modus_sdk::export!(Plugin);

// Ниже в файле — log_bus, payload_kind, payload_text. Только печать текста, для
// первого успеха не трогайте.
```

## Свой текст: `--inject`

Без флага `dev` сам кладёт `fixture hello` и донат. `--inject` **заменяет** эту пару вашим файлом: одного объекта достаточно.

Создайте `bus/inject.json` (не JSONL, не массив):

```json
{
  "type": "message",
  "user_id": "you",
  "display_name": "you",
  "fragments": [{ "type": "text", "text": "hello from me" }]
}
```

- `type` — вид события на шине. Сейчас только `message`.
- `user_id` / `display_name` — кто «написал». Для лога consumer важнее текст.
- `fragments` — куски тела, не HTML. `type: text` + `text` — обычная строка.

Запуск:

```powershell
modus dev bus --inject bus/inject.json
```

- `--inject` — взять события из файла вместо встроенной фикстуры.
- `bus/inject.json` — путь **относительно корня репо** (где вы стоите), не относительно `bus/` автоматически.

В логе должна появиться строка `hello from me`. Поменяйте `text`, сохраните, снова `dev` — увидите новый текст. Нет строки — опечатка в JSON или не тот путь к файлу (CLI напишет `inject: …`).

Ctrl+C, как раньше.

Следующая глава — [что плагину нельзя](04-cannot.md), даже когда `dev` уже зелёный.
