# Манифест consumer

Если это первый плагин — откройте файл, который написал `new`. Полная таблица полей (хосты, слоты, auth) — [api/манифест](../api/00-manifest.md).

Файл называется `manifest` **без** расширения. Это JSON. Путь: `bus/manifest` (или тот `--dir`, что вы указали).

```powershell
Get-Content bus/manifest
```

- `Get-Content` — напечатать файл в терминал (можно открыть и в редакторе).
- `bus/manifest` — путь от корня репо. Не `manifest.json`.

Для команды из [главы `dev`](03-dev.md) вы увидите:

```json
{
  "id": "com.you.bus",
  "name": "bus",
  "version": "0.1.0",
  "author": "author",
  "abi": 2
}
```

- `id` — кто этот плагин для хоста. Reverse-DNS, как в `new --id`. Смена `id` = **другой** плагин: повторная установка не продолжит старые настройки. Не переименовывайте «для красоты».
- `name` — человеческое имя в списке. Его можно поменять. По умолчанию — последний кусок `id` (`bus`). Не путать с `id`.
- `version` — версия **вашего** пакета (`0.1.0`, потом `0.1.1`, …). Не версия языка с хостом.
- `author` — подпись автора. По умолчанию строка `author`, если в `new` не было `--author`.
- `abi` — версия языка между плагином и приложением. Сейчас только **`2`**. Это не `version` пакета. Не ставьте `1` и не поднимайте «на всякий случай».

Поля всего пять. Так и должно быть.

Нет `capabilities` — нормально. Слушать шину можно без списка прав. Не копируйте в consumer чужой манифест с `hosts`, `auth_mode` и `client_id`: это коннектор, сеть вам от этого не появится, а `pack` начнёт требовать импорты, которых в каркасе нет.

Не добавляйте `client_secret`. Секрет в манифесте — отказ.

Можно поправить `name` и `author`, сохранить, снова `modus dev bus` — в первой строке лога `dev …` останется тот же `id`, имя в UI Core вы увидите при установке `.mplug`.
