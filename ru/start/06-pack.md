# Упаковать и поставить

Если это первый плагин — дойдите до файла `.mplug` на диске. Установка в приложение — последняя проверка, не способ отладки. Если нужна таблица zip и полей пакета — [справочник](../README.md#справочник).

Команды — из корня clone `modus-sdk`. Функция `modus` — [глава про инструменты](01-tools.md). Рядом удобно держать [modus-examples](https://github.com/CaptainGnome/modus-examples).

## Pack

```powershell
modus pack bus
```

- `pack` — собрать **release**-wasm, проверить права, записать пакет. Это не `dev`: другой профиль, без учебного хоста, без `fixture hello` в терминале.
- `bus` — `[PATH]`: каталог crate, как у `dev`. Не файл `.mplug`.

Вы увидите `packed bus\dist\bus.mplug` (на Windows слэш может быть `\`). Имя файла = имя **каталога**, не `id`.

Внутри zip два обязательных файла:

- `manifest` — тот же паспорт, что в `bus/manifest`;
- `module.wasm` — компонент (не «сырой» wasm после `cargo build` вручную). Сборка **release**, не debug из `dev`.

Папки `assets/` у каркаса consumer нет — в zip её не будет. Так и должно быть.

Нет файла после ошибки — `pack` его не пишет. Частые тексты: `Need target wasm32-unknown-unknown`, `cargo build failed`, нет `manifest`. Чините причину, не копируйте чужой `.mplug`.

Токен и `inject.json` в пакет **не** попадают. Туда попадает только то, что в каталоге crate (манифест, wasm, `assets/`).

## Check отдельно не обязателен

`pack` сам гоняет ту же проверку, что `check`. Без успеха файла нет.

Если хотите проверить уже готовый пакет:

```powershell
modus check bus/dist/bus.mplug
```

- `check` — прочитать манифест и wasm, сверить импорты с правами. Ничего не запускает.
- `bus/dist/bus.mplug` — путь к пакету. Можно передать каталог crate (`bus`) — тогда CLI сам пересоберёт wasm и проверит его.

Успех: `ok com.you.bus …`. Отказ — в stderr, файл pack не трогает.

## Поставить в Modus

Отладка по-прежнему [`modus dev`](03-dev.md). Чтобы увидеть пакет в списке как стример, нужен **установленный** Modus (готовое приложение), не checkout продукта и не `npm` / `tauri`.

1. Откройте Modus.
2. В шапке: **Установить плагин** (или «Плагины» → «Установить»). Выберите `bus\dist\bus.mplug`. Либо перетащите `.mplug` на окно.
3. Диалог **Разрешить плагин?** покажет имя, id, версию, автора. У consumer права — «только базовый API». Списка хостов нет: сети в манифесте нет. Подтвердите.

Пакет должен появиться в «Плагины» со статусом «работает». Лог гостя — кнопка **Логи**.

Пустая лента при одном consumer — **не баг**. Слушатель не кладёт события на шину. В `dev` их клал учебный хост. В приложении нужен источник: учебный emitter или уже стоящий коннектор площадки.

Источник шины (учебный emitter из [modus-examples](https://github.com/CaptainGnome/modus-examples)):

```powershell
modus pack ../modus-examples/emitter
```

- путь — от корня clone `modus-sdk`, если `modus-examples` лежит рядом (sibling).

Поставьте ещё `..\modus-examples\emitter\dist\emitter.mplug`. В логе consumer появятся события (в `dev` это был текст `fixture hello`; здесь источник — пакет emitter). Только ваш `.mplug` без источника — тишина, каркас живой.

Не отлаживайте правки `lib.rs` установкой пакета. Снова `modus dev bus`, и только потом `pack`.

Часть 1 на этом закрыта: consumer в `dev` и файл `.mplug`. Следующая глава — [коннектор](07-connector.md), по желанию; или [дальше](08-next.md).
